# Autonomous Agentic Game Studio Harness & Observability Platform

An autonomous, requirement-driven multi-agent game studio harness that scans a player's local Steam library, extracts their behavioral **Steam Player DNA**, pairs the human Executive Producer with an interactive 1-on-1 **Creative Co-Producer** (`CoProducerAgent`) who also chairs a **10-Specialist Creative Writers' Room** (4 Council Leads + 6 Specialized Sub-Agents), seeds every **Living Game Bible** from a first-principles **Genre Craft & Fun Foundation** (`GenreCraftFoundation`), and dynamically orchestrates **Continuous Production Board** **Task Lead Strategists** and domain specialists (`visual_artist`, `visual_evaluator`, `audio_designer`, `audio_evaluator`, `script_writer`, `swe_engineer`, `qa_test_engineer`) to specify, illustrate, voice-act, code, instrument, playtest across multi-horizon event-driven QA keyframes, and sign off on an original **Godot 4.3** game from scratch—then continuously evolves the game across vertical slices based on blind playtester telemetry and live SQLite WAL observability.

---

## Core Architecture

### 1. Steam Library Discovery & DNA Profiler (`engine/steam/`)
- Parses local macOS Steam VDF configurations (`libraryfolders.vdf`, `localconfig.vdf`, `appmanifest_*.acf`) and enriches top-played titles via the Steam Store API.
- Computes genre affinities, continuous pacing preference (`tactical_methodical` to `kinetic_high_mobility`), challenge tolerance, and aesthetic palette mood.

### 2. Interactive Creative Co-Producer, Hierarchical Creative Writers' Room & Living Game Bible (`engine/studio/coproducer.py`, `engine/studio/writers_room.py`)
- **Interactive 1-on-1 Creative Co-Producer & Specialist Council Chair (`CoProducerAgent`, `COUNCIL_CHAIR_ROLE = "CoProducer"`)**:
  - Unifies pre-genesis concept drafts (`cartridges/_coproducer_drafts/draft_*`) and built/in-progress game cartridges as persistent 1-on-1 Co-Producer sessions (`co_producer.json` + `co_producer_brief.json`, mirrored to `studio_coproducer_threads` and `studio_coproducer_messages` in SQLite WAL).
  - Runs a bounded multi-step tool loop (`curate_genre_fun_foundation`, `consult_council`, `dispatch_specialist_probe`, `sketch_multimodal_concept`, `query_game_memory`, `inspect_game_state`), curating which visual sketches or consultation cards appear inline by default (`presented_card_ids` / `show_by_default`) while preserving full prompt, tool, and deliberation traces inside expandable Behind-the-Scenes observability drawers.
  - Supports confirmation-gated game commissioning (`commission_game` with `refined_concept` handoff or `loose_spark` full brainstorm) and a **Three-Tier Mid-Game Pivot Engine**: Tier 1 (`pivot_course_correction` live Council steering), Tier 2 (`pivot_structural` pausing the daemon, resetting affected `ProductionBoard` tasks, updating `GameBibleSpec`, and resuming), and Tier 3 (`pivot_fork_cartridge` cloning a verified checkpoint or build into an isolated branch cartridge while keeping the original intact).
  - Actively participates in and **leads** the Specialist Council (`"Co-Producer (Council Chair)"`), carrying 1-on-1 Executive Producer session memory (`_load_coproducer_session_context`) directly into Council deliberations, actively listening/interjecting/routing the floor in `run_writers_room`, and chairing Concept Genesis, Refined Concept Handoff (`run_refined_concept_handoff`), convergence checks, `CouncilSteeringRoutingPlan`, `ProductionBoard` proof reviews (`_reviewer_for`), Blind Playtest verdicts (`record_milestone_notice` synced back to `co_producer.json`), and `NextSliceStrategyPlan`.
- **First-Principles Genre Craft & Fun Foundation (`GenreCraftFoundation`, `GenrePillarSpec`)**:
  - Every Living Game Bible starts at Turn 0 (or via `curate_genre_fun_foundation` during 1-on-1 ideation) with `ContextCuratorAgent.synthesize_genre_craft_foundation`, grounding the studio in the target genre's `core_fun_thesis`, 3–5 evolvable `foundational_pillars` (`pillar_id`, `player_promise`, `what_makes_it_fun`, `minimum_slice_0_expression`, `failure_mode_if_missing`), `bootstrap_to_mastery_arc`, `spatial_and_ux_precision_contracts`, and `genre_anti_patterns_to_never_commit`.
  - Indexed semantically (`bible:genre_craft_foundation`) and evolved in-place (`genre_craft_foundation` updates on `WritersRoomTurnProposal`, `SliceStateReflectionTurn`, and `NextSliceStrategyPlan`) as the game matures across slices.
- **Emergent Concept Genesis & Hierarchical Specialist Roster (`CreativeWritersRoom`)**:
  - Convenes 4 **Core Council Leads** (`CoProducer` as Council Chair, `GameplayDesigner`, `StoryWorldArchitect`, `VisualArtDirector`) and 6 **Specialized Sub-Agents** (`LevelAndProgressionDesigner`, `GameplaySystemsEngineer`, `ScriptwriterAgent`, `CharacterDesigner`, `UXExperienceDesigner`, `AudioAtmosphereDesigner`) — 10 Council specialists total (preserving backward-compatible alias resolution for legacy `CreativeDirector` transcripts).
  - Generates orthogonal creative provocations (`CreativeProvocationSet`), collects independent domain fragments (`ConceptFragment`), collides them into candidate premises (`ConceptCollisionProposal`), verifies novelty against prior studio games (`NoveltyJudgement`), and ensures all core gameplay/level/systems/art/UX/audio specialists contribute (`_missing_required_board_specialists`) before locking a full Production Board build.
- **Upfront 16:9 Concept Art Mockup, Earned-Agency Design Contracts & Iterative Vertical Slices (`GameBibleSpec`, `GameSliceSpec`)**:
  - Synthesizes an upfront 16:9 Concept Art Mockup establishing the game's visual target, camera/spatial paradigm, and color palette (`visual_mockups`), while deferring character portraits and voice barks to just-in-time slice tasks.
  - Plans an iterative `slice_roadmap` (`Slice 0` vertical slice onward) and supports post-drain iterative expansion (`run_slice_expansion`, `POST /api/studio/next-slice`).
  - Authors a cohesive whole-game design blueprint aligned around **earned player agency** (zero self-completing loops):
    - `LevelGenerationStrategy`: Bespoke `generation_approach`, `world_structure`, `runtime_construction_plan`, `level_archetypes`, and `generation_rules`, validated against `LevelLayoutSpec` (`validate_level_layout`) so multi-archetype worlds span multiple connected regions and viewports.
    - `CoreLoopSpec` (with explicit `agency_and_decision_loop` and `earned_vs_given_progression`), `EngagementPlan`, `OnboardingPlan`, and `GoalHierarchy` across multiple player horizons.
    - `MechanicEngineeringSpec` (`technical_architecture_blueprint`): Godot 4 node/collider topology, `1:1` `get_global_mouse_position()` world-click coordinate mapping with strict `CanvasLayer` HUD separation, crisp downsampling (`scale <= 1.0`), deterministic state machines unsolved at `t=0`, required sprite/tile/animation assets, and falsifiable test invariants.
- **Continuous Production Board, Two-Stage Council Task-Shaping, Dynamic Task Spawning & Whole-Game Slice Assembly Check (`engine/studio/production_board.py`, `engine/studio/writers_room.py`)**:
  - Before workers claim unstarted items, `_run_council_task_shaping_round` runs a **Two-Stage Council Task-Shaping Pass**: Stage 1 decomposes monolithic tasks (`action="split"`, automatically re-pointing downstream dependents) and raises missing active-slice companion tasks (`backlog_additions`); Stage 2 (`_run_full_council_direction_pass`) runs all relevant Council specialists in parallel to enrich every task with cross-domain direction (`action="enrich"`) over disjoint per-feature GDScript paths (`scenes/mechanics/*.gd`, `scenes/entities/*.gd`, `scenes/ui/*.gd`).
  - Specialists and Task Leads raise and dynamically spawn (`action="spawn_tasks"`, `spawn_tasks_from_item`) dependency-linked `WorkItemProposal` tasks (`visual_asset`, `animation`, `audio_asset`, `level_map`, `mechanic_code`, `ui`, `integration`) onto `ProductionBoard` (`backlog.json`).
  - Every completed item returns visual/waveform/audiovisual/script proof artifacts (`.png` plates/filmstrips, `.wav` audio cues, and synchronized `.mp4` clips attached via `_proof_parts`) inspected by a cross-functional Specialist Council panel (`_reviewers_for`) in a sequential **Conversational Proof Review Roundtable** (`_run_review_round`, `ReviewBatch.spoken_dialogue`, `ReviewDecision.validation_criteria_for_my_role`), where each specialist determines from first principles what must be validated for their discipline (including human-scale responsiveness over time and subsystem harmony), inspects ground-truth verification artifacts (`qa_test_script_source` from `tests/test_<id>.gd`, SHA-256 `[VERIFIED DISK DIFF]`, runtime `visible_ui_texts`, `audio_players_detail`, and `main_scene_parity`), converses with fellow panelists on the proof artifacts, and requires unanimous approval (`ReviewBatch`, `ReviewDecision`, `CapDecision`) while streaming the review dialogue and inline filmstrip cards to the Writers' Room transcript.
  - Items that fail worker execution twice in a live build automatically escalate to Council `needs_decision` (`escalate_failed_to_decision`) with the exact worker failure trace so the Council can `rewrite_spec` or `cancel` and re-point dependents.
  - **Automated Slice Playtest Script & Council Playtest Roundtable (`_run_slice_assembly_check`, `SlicePlaytestRoundtableTurn`, `SliceAssemblyDecision`)**: Whenever the active Production Board drains, `QATestEngineer` authors and executes a dedicated **Slice Playtest Script** (`res://tests/test_slice_playtest_<slice_id>_pass<N>.tscn` + `.gd`) that instantiates the live game entrypoint (`res://main.tscn`), attaches test-only diagnostic overlays and telemetry (`player_pos`, velocities, goal state), and scripts real player `input_segments` to play through at least the first goal of the current slice (`filmstrip_slice_assembly_check_pass*.png`)—or reports a `production_defect_report` if the production game itself is broken or deadlocked. The Council (`GameplayDesigner`, `UXExperienceDesigner`, `VisualArtDirector`, and Chair `GameplaySystemsEngineer`) then holds a multi-perspective **Slice Playtest Roundtable** in the Writers' Room inspecting the exact test script source, live `res://main.tscn` parity telemetry, visible HUD text, audio playback state, and entrypoint reachability (`compute_entrypoint_reachability`), spawning fix/integration tasks (`is_slice_assembled=False`) if any gap is found.
  - **Automated End-of-Slice Blind Playtest & Skeptical Council Audit (`_run_end_of_slice_blind_playtest`, `BlindPlaytestCouncilTurn`, `BlindPlaytestCouncilVerdict`)**: Immediately after `_run_slice_assembly_check` passes, the Council dispatches the zero-leak `BlindPlaytesterAgent` (`initiated_by="council"`) to play the slice cold as a first-time human player. Upon completion, the session's synthesized `PlaytestExperienceReport` (`overall_fun_rating` `1..10`), 6-pillar player impressions, field notes, open/answered questions, live bug reports, discovered rulebook, chronological player action tape, up to 5 evenly-spaced mid-session screenshots (`first -> quarter -> mid -> three-quarter -> final`), and all generated `PlaytestWishDraft` items (`status="sent_to_council"`) are delivered to the Council (`GameplayDesigner`, `UXExperienceDesigner`, `VisualArtDirector`, `AudioAtmosphereDesigner`, and Council Chair `CoProducer`). The Council cross-examines reported ratings against actual player inputs—explicitly auditing against passive/self-playing loops or zero-effect `noop`/click stalls—to decide whether to `iterate_current_slice` (spawning targeted `ProductionBoard` fix/polish tasks) or `approve_slice` (preserving non-overwriting per-pass artifacts `artifacts/blind_playtest_report_<slice_id>_pass<k>.json`, stamping the Council verdict onto the archived playtest session, syncing a milestone summary notice back to `co_producer.json`, and advancing cleanly across the full `slice_roadmap` without redundant post-board asset re-rendering or duplicate Gate F re-audits).
  - **Agent-Verified Board Promotion (`is_agent_verified_board_build` in `StudioOrchestrator.execute_swarm_plan`)**: Continuous Production Board builds rely on autonomous agent discovery, Task Lead & specialist verification, Slice Assembly Check, End-of-Slice Blind Playtest, and Council Proof Review Roundtables rather than hardcoded post-slice or post-build 5-Gate restrictions—verifying only headless Godot boot/syntax integrity (`verify_gate_a_syntax_and_entrypoint`, escalating any boot syntax error directly to the Writers' Room Council) before promoting cleanly to `cartridges/active/`.
  - **First-Principles Slice Reflection & Next-Slice Strategy Roundtable (`_run_slice_reflection_and_strategy`, `SliceStateReflectionTurn`, `NextSliceStrategyPlan`)**: Before advancing to Slice `#N+1`, Council specialists hold a reflection roundtable examining the current build and blind-playtest experience dossier from first principles (first-time player `t=0` mental model, causal reachability & loop depth, systemic coherence across controls/camera/spatial/audio/scale, and short/mid/long-term goals), evolve `genre_craft_foundation` pillars in-place as needed, curate persistent cross-slice long-term memories (`memory_updates`: marking delivered `[mem_...]` goals `fulfill` and carrying genuinely deferred multi-slice goals or systemic lessons forward), synthesize a cohesive `NextSliceStrategyPlan` chaired by `CoProducer`, and raise the Slice `#N+1` Production Board backlog until all planned roadmap slices are completed.
- **Live Executive Producer Steering, Playtest Report Dispatch, Auto-Wake & Greenlight Gate**:
  - Supports live mid-session, mid-production, and post-drain steering (`POST /api/studio/greenlight`, `POST /api/writers-room/steer`, `POST /api/playtest/wishes/send-to-council`, and `POST /api/playtest/sessions/{session_id}/send-report-to-council`) persisted via `.pending_steering.json` and `game_bible.json` (with multimodal player proof screenshots copied into `artifacts/proofs/` and drained cleanly across board execution, slice reflection, and slice expansion boundaries). Injecting steering or dispatching a manual playtest report while the studio is idle automatically wakes `StudioDaemon(resume_current=True)` in the background and runs code-grounded multi-specialist pivot turns (`_execute_steering_pivot_turns` routed by Council Chair `CoProducer` via `CouncilSteeringRoutingPlan` across `CoProducer`, `LevelAndProgressionDesigner`, `GameplayDesigner`, `UXExperienceDesigner`, and `GameplaySystemsEngineer`) that update the Living Game Bible, refine unstarted tasks (`backlog_refinements`), and raise concrete `backlog_additions` tasks on the Production Board.

### 3. Semantic Context Curator, Iterative Task Lead Strategist & Asset/Audio Engines (`engine/studio/`)
- **Semantic Context Curator, Genre Craft Synthesis, Entrypoint Topology, Self-Inquiry Memory & Prefix-Cache-Aligned Prompts (`engine/studio/context_curator.py`)**:

- **Per-Game Multi-Bank Long-Term Memory (`engine/studio/game_memory.py`)**:

- **Iterative Task Lead Strategist, Tool Discovery & Peer Specialist Rerouting (`engine/studio/workers.py`, `engine/studio/tool_registry.py`)**:

    - `audio_evaluator`: Invokes `AudioEvaluatorAgent` (`engine/studio/audio_evaluator.py`, powered by `gemini-3.8-flash` via the Gemini Interactions SDK) to perform rich perceptual listening QA on isolated `.wav` cues, multi-layer mixes, or synchronized gameplay `.mp4` clips against open-ended Task Lead evaluation prompts (`AudioEvaluationReport`), enriching `assets/asset_library.json` with `perceptual_description`.

    - `swe_engineer`: Authors/updates modular GDScript files (`main.gd`, `scenes.gd`, `mechanics.gd`, `entities.gd`, `ui_hud.gd`, and decomposed submodules under `scenes/{mechanics,entities,ui}/*.gd` or `scripts/*.gd` via `CodeImplementationPlan.module_path`) using full target-module source and cross-module signature summaries (`_summarize_non_target_gd_module`, guarded by `_validate_no_large_file_clobber` so unread summarized modules are inspected via `self_question` before editing), or generates machine-readable `LevelLayoutSpec` data (`level_map_<item_id>_rev<N>.png`), gated by per-task `allowed_files`-scoped headless Godot compiler & runtime smoke checks and recorded with unified diffs (`code_diffs`).
    - `qa_test_engineer`: Designs a scripted `FilmstripPlan` (`simulation_ticks <= 3600` for up to `60s` simulated play, event-driven `keyframe_triggers` via `QAKeyframeTrigger` supporting `at_tick`, `on_condition`, and `on_change` alongside `capture_ticks`, `input_segments` including `mouse_world_pos` / `mouse_click_pos` / reactive triggers, `setup_calls`, `state_assertions`, `record_audiovisual_clip`, `test_scene_gd_content` written to `res://tests/test_<item_id>.tscn` + `.gd`, or `production_defect_report` to surface broken/deadlocked production code back to `TaskLead` without faking state mutations) and runs `capture_filmstrip` / `capture_audiovisual_mp4` (`engine/studio/proofs.py`, `engine/sim/godot_verifier.py`, `engine/sim/godot_harness.gd`) at `--fixed-fps 60 --headless` with Counterfactual Idle vs. Active Action verification to record a labelled multi-horizon Godot gameplay proof contact sheet (`filmstrip_<item_id>_rev<N>.png`), optional synchronized H.264 + AAC gameplay proof clip (`audiovisual_<item_id>_rev<N>.mp4` via `--record-audiovisual`), and rich telemetry sidecar (`.telemetry.json` including `keyframe_events`, `visible_ui_texts`, `audio_players_detail`, and `main_scene_parity`).
  - **Granular Per-File Locking (`FileLockTable`) & Cooperative Non-Blocking Yielding (`WorkerYielded`)**: Concurrent `swe_engineer` tasks acquire per-file locks (`FileLockTable.acquire_many` in sorted lexical order) on only the target `.gd` modules they touch (`waiting_on_locks`), enabling parallel GDScript engineering across disjoint files. When a required file lock or `code_lock` is held by another worker, the Task Lead persists its `pending_decision`, `turns`, and `collected_proofs` to `lead_trace_rev{N}.json` and raises `WorkerYielded` (`yield_item`) so the worker thread immediately moves on to other ready tasks and resumes at the exact paused turn once the lock frees.

### 4. 6-Gate Headless QA Playtester & Multi-Agent Final Sign-Off Council (`engine/supervisor/`, `engine/sim/`)
- **Gate A (Syntax, AST & Entrypoint)**: Validates Godot 4.3 headless compiler diagnostics (`verify_godot_cartridge_syntax`), AST security invariants, and Rule 4 Rationale-First contracts.
- **Gate B (Multimodal Asset Integrity)**: Verifies RIFF `.wav` audio headers, `.png` sprite/portrait integrity, and acyclic dialogue graphs.
- **Gate C (Headless Execution, Real GPU Viewport Capture & Scene Audit)**: Executes the cartridge via `godot_harness.gd` / `GodotHeadlessSimulator`, supporting scripted input ranges (`--input-script`) and QA scenario setup calls (`--setup-script`), capturing `t=0s`, `t=end`, multi-tick filmstrips, and collision-overlay screenshots, auditing the live scene tree, and flagging passive auto-win or unbounded sky-or-void states.
- **Gate D (60 FPS Frame Budget)**: Verifies tick execution stays within the 16.6ms frame budget.
- **Gate E (Custom Telemetry Emission)**: Verifies that custom probes declared in `telemetry_manifest.json` actively emit into SQLite WAL during simulation.
- **Gate F (Challenger Gate & Multi-Agent Final Sign-Off Council)**:
  - Independent Gemini structured evaluation (`ChallengerGate`) grounded in AST inspection, runtime telemetry, and scene audits verifying 100% of acceptance criteria.
  - **Multi-Agent Specialist Sign-Off Council (`run_final_signoff_council`)**: Each creative specialist inspects the rendered candidate build (`playtest_t0.png`, `playtest_tend.png`, `playtest_collision_overlay.png`) to issue a domain sign-off (`SpecialistSignOffVerdict`) before atomic promotion to `cartridges/active/`.

### 5. Decoupled Blind Playtester Agent, Session History Archive & Dual-Mode Replay Theatre (`engine/playtest/`)
- **Strict Zero-Leak Player Isolation & Desktop Mouse Parity (`BlindPlaytesterAgent`, `BlindStoreCard`, `GodotPlaytestBridge`)**:
  - Plays any verified game checkpoint cold as a genuine external human player—with **zero access** to `.gd` source code, `GameBibleSpec`, `backlog.json`, or internal engine state snapshots—seeing only a Steam-style `BlindStoreCard` (`game_title` + short pitch), live 1280×720 game viewport screenshots, and captured in-game audio clips via `godot_playtest_runner.gd` (with `0..1000` normalized screen-coordinate smooth cursor pointing, `Viewport.push_input` parity without hijacking the host OS desktop mouse cursor, and a desktop pointer arrow overlay that yields cleanly to custom in-game cursors). Whenever the playtester wants a deeper perceptual check over meaningful gameplay time rather than a single sub-second turn slice, `PlaytestTurnDecision.request_audio_evaluation` (`PlaytestAudioEvaluationRequest`, `lookback_seconds` `2..20s`) and `PlaytestTurnDecision.request_visual_evaluation` (`PlaytestVisualEvaluationRequest`) mux a pure `1280×720` rolling gameplay `.mp4` (`extract_recent_gameplay_clip_mp4`) and dispatch `AudioEvaluatorAgent` / `VisualEvaluatorAgent` with `curate_studio_context=False`, returning the perceptual critique on the next turn without leaking any studio context.
- **Rich Player Memory, Experience Reports, Session Archive & Broadcast Video (`PlaytestSessionManager`)**:
  - Executes motor actions (`PlaytestMotorAction`), discovers controls and mechanics empirically into `rulebook_json` (`PlaytestRulebookUpdate`), maintains persistent **Player Field Notes** (`field_notes_json`), **Questions & Hypotheses** (`questions_json`), and **Live Bug Reports** (`bugs_found_json`), records sparse genuine-shift emotional progression (`PlaytestMoodNote`), and logs non-repetitive impressions across 6 experience pillars (`PlaytestImpressionUpdate`: `graphics_and_visuals`, `gameplay_and_feel`, `sound_and_audio`, `intuitiveness_and_controls`, `goals_and_pacing`, `world_and_atmosphere`), carrying full player memory across `30`-turn `PlaytestCompactedJournal` compactions without breaking byte-0 prefix caching.
  - Indexes every session chronologically per game (`Run #1..N`) and per slice (`Pass #1..M`) via `list_enriched_sessions`, snapshots session summaries into `<cartridge>/artifacts/playtest_sessions/<sid>.json` + `session_archive.json` (with automatic SQLite recovery if pruned), stamps Council slice verdicts (`record_council_verdict`), synthesizes a rationale-first `PlaytestExperienceReport` (`session_report_json`, `overall_fun_rating` `1..10`), and composites a synchronized `1600×720` side-by-side HUD broadcast MP4 (`replay.mp4`, with on-demand unmuxed-frame recovery via `_recover_unmuxed_session_video`). **Reset** protects recorded historical runs (`confirm_delete=True`) while allowing clean restarts of in-flight sessions.
  - Enforces a strict `initiated_by` (`"council"` vs `"operator"`) delivery boundary: automated end-of-slice Council runs auto-deliver the experience report and all `PlaytestWishDraft` items (`status="sent_to_council"`) into Council deliberation, whereas manual operator runs stay out of Council context until the Executive Producer explicitly forwards selected wishes (`POST /api/playtest/wishes/send-to-council`) or dispatches the **Full Playtest Experience Report** (`POST /api/playtest/sessions/{session_id}/send-report-to-council`, `dispatch_session_report_to_council`) complete with 6-pillar impressions, bugs, open/answered questions, field notes, rulebook, optional pending wishes, optional Producer direction, and up to 5 evenly-spaced session screenshots (`artifacts/proofs/manual_playtest_*.png`).

## Quickstart

### 1. Environment Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cd studio-web && npm install && cd ..
cp .env.example .env
# Edit .env and set GEMINI_API_KEY
```

### 2. Launch the Autonomous Studio ("Mission Control")

Start the Studio observability API server and background daemon in one terminal:

```bash
python run_studio.py --port 8000
```

Or resume/advance an existing candidate build directly from its persisted Living Game Bible and slice roadmap:

```bash
python run_studio.py --port 8000 --resume
python run_studio.py --port 8000 --candidate candidate_genesis_db8d94 --feedback "Expand mid-game progression depth"
```

Start the React Mission Control dev server in a second terminal:

```bash
cd studio-web && npm run dev
```

Open **`http://127.0.0.1:5173`** in your browser (`http://127.0.0.1:8000` also redirects automatically to the Vite UI in dev mode, or serves `studio-web/dist/` directly when built) to watch the Creative Writers' Room brainstorm the Living Game Bible, steer or greenlight the concept, monitor the Production Board & Playtest Lab, and inspect verified checkpoints.

### 3. Play the Generated Game (or Any Verified Checkpoint)

Launch the promoted active cartridge natively in Godot 4.3 at 60 FPS:

```bash
python run_game.py
```

Or launch and compare incremental requirement checkpoints (`R1`, `R2`, ..., `R5`):

```bash
python run_game.py --list-checkpoints
python run_game.py --latest-checkpoint
python run_game.py --checkpoint candidate_genesis_db8d94_R1
```

### 4. Run Typecheck & Hermetic Test Suite

All unit and integration tests run hermetically and in parallel via `pytest-xdist` (`-n auto --dist worksteal` in `pytest.ini`; `tests/conftest.py` redirects `TELEMETRY_DB_PATH` to an isolated temporary SQLite database, enforces headless `SDL_VIDEODRIVER=dummy` so tests never touch the host desktop mouse cursor, and blocks unmocked external LLM or HTTP network calls):

```bash
pytest
cd studio-web && npm run typecheck && npm test
```
